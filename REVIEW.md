# REVIEW.md

## Identified Defects in Starter `app/main.py`

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` (lines 72-74) | Returns `{"status": "ok"}` statically without testing if MongoDB is actually reachable or responding to commands. | Stop or disconnect MongoDB; `GET /health` still returns 200 OK instead of 503 Service Unavailable. | Implemented `client.admin.command("ping")` inside a `try/except` block and raise HTTP 503 if ping fails. |
| 2 | `create_employee` (lines 77-85) | Race condition: uses check-then-insert (`find_one` followed by `insert_one`). Concurrent requests with the same `emp_code` both pass the check and attempt to insert. | Send two concurrent `POST /employees` requests with identical `emp_code`. Both succeed or create duplicates. | Created a unique index on `employees.emp_code` at startup and catch PyMongo `DuplicateKeyError` to return HTTP 409. |
| 3 | `create_employee` (line 82) | Uses `datetime.now()` to populate `created_at`, storing a naive local datetime rather than a UTC instant. | Run on a server in non-UTC timezone; stored MongoDB BSON date reflects local offset instead of UTC. | Used `datetime.now(timezone.utc)` and truncated to whole seconds per R1 before storing in MongoDB. |
| 4 | `create_employee` (line 85) | Returns document with `created_at` as a Python/BSON datetime object instead of integer epoch milliseconds. | Client response validation against OpenAPI contract fails with type error (`created_at` expected `integer` epoch ms). | Converted `created_at` to integer epoch milliseconds in `serialize_employee` helper before returning. |
| 5 | `create_employee` / `EmployeeIn` (lines 53-61, 77-85) | Does not validate that `shift_start` differs from `shift_end` as required by OpenAPI spec. | Submit `{"shift_start": "09:30", "shift_end": "09:30"}`; accepted with 201 instead of 422. | Added a Pydantic `@model_validator` that raises a ValueError (HTTP 422) when `shift_start == shift_end`. |
| 6 | `EmployeeIn` (lines 53-61) | Missing string constraints and regex validations for `emp_code` (`^EMP\d{4,6}$`), `email`, and string lengths. | Send invalid `emp_code="123"` or invalid email; accepted instead of returning HTTP 422. | Added Pydantic `Field` patterns, `min_length`, `max_length`, and regex constraints according to `openapi.yaml`. |
| 7 | `list_employees` (line 93) | Incorrect pagination skip formula: `skip = page * page_size`. For `page=1, page_size=20`, it skips 20 items and returns page 2! | Request `GET /employees?page=1`; returns empty list when collection has fewer than 20 items. | Fixed skip calculation to `skip = (page - 1) * page_size`. |
| 8 | `list_employees` (line 94) | `total` is calculated using `db.employees.count_documents({})`, which counts the entire collection ignoring the `department` filter. | Request `GET /employees?department=Sales`; `total` shows 6 instead of the count of Sales employees (2). | Changed to `db.employees.count_documents(q)` so `total` accurately reflects the filtered count. |
| 9 | `list_employees` (line 95) | Does not sort employees by `emp_code` ascending as required by the specification. | In a database with multiple documents inserted out of order, items are returned in arbitrary natural order. | Added `.sort("emp_code", ASCENDING)` to the query cursor. |
| 10 | `list_employees` (lines 95-96) | Returns `created_at` as BSON datetime instead of epoch milliseconds. | Schema validation failure against `Employee` definition in OpenAPI specification. | Mapped each item through `serialize_employee` to convert `created_at` to integer epoch milliseconds. |
| 11 | `punch_in` (lines 99-105) | Race condition: uses check-then-insert (`find_one` then `insert_one`). Concurrent punch-ins for the same employee and date both insert. | Send parallel punch-in requests for same date; both succeed with 201 or create duplicate attendance logs. | Enforced a unique compound index on `attendance_logs.(emp_code, date)` and catch `DuplicateKeyError` to return HTTP 409. |
| 12 | `punch_in` (line 101) | Does not verify if employee exists before proceeding; if unknown, `emp["shift_start"]` raises an unhandled `KeyError` resulting in HTTP 500. | Send punch-in for unknown employee `emp_code="EMP9999"`; returns 500 Internal Server Error instead of 404. | Added explicit check `if not emp: raise HTTPException(404, "Employee not found")`. |
| 13 | `punch_in` (line 102) | `datetime.fromtimestamp(body.punched_at / 1000)` creates a naive local datetime rather than a UTC/IST aware instant. | Punches on a machine in IST or US timezones store incorrect UTC BSON timestamps in MongoDB. | Converted epoch ms to UTC timezone-aware datetime: `datetime.fromtimestamp(ms / 1000, tz=timezone.utc)`. |
| 14 | `punch_in` (line 102) | Does not truncate instants to whole seconds before calculations and storage per rule R1. | Input `punched_at=1783312500900`; stored with sub-second milliseconds instead of truncated value `1783312500000`. | Implemented `truncate_epoch_ms` (`(epoch_ms // 1000) * 1000`) applied to all incoming timestamps. |
| 15 | `punch_in` (line 103) | `ts.date().isoformat()` determines attendance date using local date, completely ignoring overnight shifts crossing midnight (R1). | For an overnight shift (22:00-06:00), a punch-in at 02:00 IST gets assigned today's date instead of previous day's shift date. | Implemented `determine_attendance_date` with IST conversion and overnight shift rule: IST time < `shift_end` belongs to previous day. |
| 16 | `punch_in` (line 119) | Injects internal MongoDB ObjectId as `doc["id"] = str(res.inserted_id)`. The OpenAPI contract has no `id` property. | Inspect punch-in JSON response; unexpected extra field `"id"` violates contract schema. | Removed `"id"` from output; attendance records are identified by natural key `(emp_code, date)` without IDs. |
| 17 | `punch_in` (lines 63-67) | Accepts any string for `status`, including non-presence statuses like `ABSENT` or `LEAVE` which cannot be created at punch-in. | Submit `{"emp_code": "EMP0001", "status": "ABSENT"}`; creates an invalid punch-in with ABSENT status. | Restricted `status` in `PunchInRequest` to `PresenceStatusEnum` (`PRESENT`, `WFH`, `ON_DUTY`); others rejected with HTTP 422. |
| 18 | `punch_in` (lines 63-67) | Accepts floating-point or seconds-looking values for `punched_at` without validation. | Submit `punched_at=1783312500.0` or `punched_at=1783312500`; accepted instead of rejected with HTTP 422. | Added `strict=True`, `ge=100000000000`, `le=4102444800000` to Pydantic Field to enforce integer epoch milliseconds. |
| 19 | `list_attendance` (line 144) | Reads entire collection into Python memory using `list(db.attendance_logs.find(q))` before sorting and slicing. | Test on a ~100k-record collection; server experiences severe latency, memory spike, or Out-Of-Memory termination. | Delegated sorting and pagination directly to MongoDB using `.sort().skip().limit()`. |
| 20 | `list_attendance` (line 145) | Sorts only by `date` descending; specification requires sorting by `date` descending, then `emp_code` ascending. | Multiple attendance logs on the same date are returned in non-deterministic order. | Applied compound sort: `.sort([("date", DESCENDING), ("emp_code", ASCENDING)])`. |
| 21 | `list_attendance` (line 149) | Converts `_id` to `id` field, violating the API schema which contains no `id` field. | Client validation fails due to extraneous `id` field and missing proper date/time serialization. | Used `serialize_attendance` to drop `_id` and serialize all timestamp fields to epoch milliseconds. |
| 22 | `list_attendance` (lines 136-141) | Missing validation for `date_from > date_to`. | Query `date_from=2026-07-10&date_to=2026-07-01`; returns empty 200 list instead of HTTP 422 per OpenAPI spec. | Added explicit validation check raising HTTP 422 if `date_from > date_to`. |
| 23 | `compute_late_minutes` (lines 33-37) | Uses naive datetime arithmetic; does not handle overnight shifts; and `int((punch_in - start).total_seconds() / 60)` truncates towards zero rather than floor. | Test punch-in at 09:40:01 for 09:30 shift: should be late 10 minutes, but naive integer math produces wrong values for edge offsets. | Implemented timezone-aware IST comparison with `math.floor` elapsed minutes strictly after grace period. |
| 24 | `compute_work_hours` (lines 40-41) | Uses Python's built-in `round()` which performs banker's rounding (round-to-even) instead of half-up rounding (R4). | Duration resulting in 4.125 hours rounds down to 4.12 with banker's rounding, but half-up requires 4.13. | Replaced with `Decimal.quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)`. |
| 25 | `compute_overtime` (lines 44-47) | Does not apply the 30-minute minimum threshold (R3). Any positive minutes were returned as overtime. | Punch-out 15 minutes after shift end: returned 15 instead of 0 (counted only when >= 30 minutes). | Added threshold condition: return minutes only when `minutes >= 30`, otherwise 0. |
| 26 | Startup (module level) | No indexes created on database startup. | First queries on large collections trigger COLLSCANs, failing performance requirements and explain checks. | Added `init_db()` in FastAPI `lifespan` handler to create unique and query indexes idempotently. |

## Examined Areas Found Correct

1. **Environment Variable Loading**:
   Using `load_dotenv(override=False)` ensures that existing OS environment variables take precedence over values in a local `.env` file, as mandated by the assignment.
2. **MongoDB Database Defaults**:
   Defaulting `MONGO_URI` to `"mongodb://localhost:27017"` and `MONGO_DB` to `"attendance_db"` matches the starter code and seed script defaults while still allowing environment overrides.
3. **Pydantic Model Separation**:
   Separating incoming request models (`PunchInRequest`, `RegularizeRequest`) from database representation and serialized output ensures internal fields (`_id`, internal metadata) never leak into API responses.
